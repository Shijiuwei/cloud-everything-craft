# Engine and license review

Reviewed September 11, 2026. These are engineering observations about upstream licensing, not a legal opinion.

## Choice

Mozilla **PDF.js 6.3.289** renders PDFs in a worker, including selectable text and current WebAssembly image decoders. **pdf-lib 1.17.1** modifies document contents, form fields, and pages. This combination provides a mature browser renderer and substantial PDF editing functionality under permissive licenses without a proprietary service, framework, or non-Puter backend.

There is no single universally best open-source PDF engine. MuPDF is a stronger integrated rendering/manipulation option, but its AGPL/commercial model is significant for this private application. We did not incorporate it or accept a paid license. PDFium has a permissive core license but would require maintaining an additional browser binding and editing abstraction. PDF.js plus pdf-lib is the pragmatic choice for the implemented feature set.

- [PDF.js project and Apache 2.0 license](https://www.jkzzc.com/seo-column/xinzhanlengqidongshoulupojushizhan-baidu-biyingyuso-mulqf4ax)

## Important observations

1. **MuPDF is AGPL or commercial.** Its vendor describes source-release obligations for AGPL use and offers commercial licensing when those obligations cannot be met. A private GitHub repository does not settle distribution or network-use obligations. MuPDF is not a dependency of this app.
2. **pdf-lib is mature but its last published release is old.** Version 1.17.1 was published November 6, 2021. It is pinned and covered by real export/reload tests. Plan for maintenance, a maintained replacement, or an internally audited fork as requirements grow. No claim is made that pdf-lib is the newest or most capable editing engine.
3. **The fontkit fork has a notice-packaging gap.** `@pdf-lib/fontkit` 1.1.1 declares MIT in package.json and its README, but the published package and repository do not contain a standalone LICENSE file. We record the declaration, attribution, and standard referenced MIT terms in `docs/fontkit-LICENSE`, preserve embedded notices in the distributed bundle, and include them in generated notices. Before public commercial distribution, confirm notice completeness with upstream or substitute an audited font implementation. This is a packaging concern, not evidence of malicious software.
4. **PDF.js has additional component licenses.** CMaps, fallback fonts, ICC data, OpenJPEG, QCMS, and JBIG2 have their own notices. The complete asset directories, including notices, are copied to `dist/pdfjs`. Do not deploy just the JavaScript bundles. In particular, `dist/pdfjs/standard_fonts` includes GPL-licensed fonts; see the redistribution section below.
5. **Noto Sans and Noto Sans KR are SIL OFL 1.1.** The fonts and their OFL notices are bundled. Korean regular and bold TrueType faces are static instances of Noto Sans KR 2.004, generated by `scripts/korean-fonts.py`; provenance and checksums are in `public/fonts/NotoSansKR-SOURCE.txt`. Lucide is ISC. pdf-lib is MIT. Other runtime dependencies have notices in `public/THIRD_PARTY_NOTICES.txt`.
6. **Puter.js is an external SDK.** It is loaded from the official v2 URL, not vendored or pinned by this repository. Authentication and file storage remain subject to Puter's service terms and SDK updates. The app does not persist access tokens itself.
7. **The bundled PDF.js standard fonts include GPL fonts; their source is redistributed.** See the section below.
8. **XMP uses @xmldom/xmldom 0.9.12 (MIT).** The parser and serializer load with document details, header/footer metadata, or edits to files containing XMP. Its license is included in the generated notices.

## Bundled fonts and GPL redistribution

PDF.js substitutes the standard 14 PDF fonts with font files shipped under `dist/pdfjs/standard_fonts/`. Two licenses apply there:

- **Liberation Sans 1.07.4** (`LiberationSans-Regular/Bold/Italic/BoldItalic.ttf`) is Copyright © 2007–2011 Red Hat, Inc., original design by Steve Matteson (Ascender Corp.), licensed under the **GNU General Public License, version 2, with a font exception**. The font exception means embedding the font in a document does not make that document GPL; it does not exempt distribution of the font files themselves, which stays under the GPL v2. These are the only GPL-licensed third-party materials the build distributes.
- **Foxit fonts** (`Foxit*.pfb`) are under a permissive BSD-3-Clause-style license (the PDFium/Foxit notice) and carry no source-redistribution obligation.

**How we meet the GPL v2 redistribution requirement (section 3).** GPL v2 requires the complete corresponding source to accompany the distributed font object code. The build satisfies this by option 3(a), shipping the source with the binaries:

- The exact upstream Liberation Fonts 1.07.4 source release is kept in the repository at `vendor/liberation-fonts/` (the fontforge-buildable `liberation-fonts-ttf-1.07.4.tar.gz`, the GPL v2 text in `COPYING`, the font-exception `License.txt`, `AUTHORS`, and `ChangeLog`), with its provenance and checksums recorded there.
- `vite.config.js` copies that directory into the build at `dist/pdfjs/standard_fonts/liberation-source/`, so the source travels next to the fonts in every deployment.
- The license text (`LICENSE_LIBERATION`, GPL v2 with the font exception) is preserved beside the fonts by PDF.js and is also reproduced in `public/THIRD_PARTY_NOTICES.txt`, which additionally records the bundled source path, the upstream download URL and checksum, and a three-year written offer for the source as a further fallback under section 3(b).

The distributed `.ttf` files are the Liberation Sans 1.07.4 fonts as vendored and byte-optimized by the PDF.js project: the typeface, the `Version 1.07.4` name record, and the font revision match upstream, and PDF.js re-compiles them so a few bytes differ from the upstream release. Under the GPL these remain the Liberation 1.07.4 fonts, for which the upstream 1.07.4 tarball is the corresponding source. The specific optimization tooling is part of PDF.js (Apache-2.0); its source is at `https://github.com/mozilla/pdf.js` under `external/standard_fonts`. When PDF.js is upgraded, re-verify the bundled Liberation version (name record and `head` font revision) and refresh `vendor/liberation-fonts/` if it changes.

If GPL redistribution is unacceptable for a given deployment, PDF.js can be built or configured to substitute non-GPL standard fonts (for example the Foxit set alone) instead of removing the assets and breaking standard-font rendering.

## Functional boundaries

- Adds text, rectangular outlines, freehand ink, and centered images to PDF page content. Supported shape paths, drawing paths, and image placements remain editable after save and reopen. Their drawing commands are transformed or removed without replacing shared image data; ancestor Form XObjects and resources are cloned for the edited occurrence.
- Text and area highlights are PDF Highlight annotations with explicit appearance streams and Multiply blending. Text selections preserve individual line and rotated-glyph geometry. Highlights can be recolored or deleted after reopening; locked highlights are left intact. Older highlights baked into page content cannot yet be selected.
- Replaces supported existing text commands while retaining surrounding content and positions. Does not reflow paragraphs, perform secure redaction, verify/create cryptographic signatures, or edit XFA forms. Text clipping, vertical/Type 3 text, alternate ActualText, inline-image streams, and some uncommon structures are not editable yet. Source commands are matched to PDF.js glyphs; an unproven match disables editing instead of changing another object.
- Text replacement is not secure redaction. Original objects may remain unreferenced in the PDF. Shared Form XObjects and resources are copied before an edit so other occurrences stay intact.
- Image manipulation supports ordinary image XObjects and enclosing rectangular/Form clipping frames. It does not yet support partially clipped images, stencil masks, inline-image streams, optional-content images, or graphics-state soft masks. Final content ordering is preserved. During a live drag, the selected image is previewed above other page content until the edit commits.
- Path manipulation supports contiguous painted paths, including Bezier curves, with ordinary RGB/gray/CMYK colors and enclosing rectangular/Form clipping frames. New freehand strokes are saved as connected paths. Legacy drawings made of separately painted segments remain separate editing units. Pattern colors, interleaved path/state commands, complex clipping, optional content, and graphics-state masks are not supported yet. Live path previews share the image preview ordering limitation.
- Existing AcroForm fields can be filled. Imported forms are flattened during merge so names cannot collide. Outlines and document-level metadata from merged files are not imported.
- Document details reconcile Info and XMP using the original modification and metadata timestamps, following ISO 32000-1 §14.3.2 and [XMP Part 3 §2.2](https://github.com/adobe/XMP-Toolkit-SDK/blob/main/docs/XMPSpecificationPart3.pdf). Edits synchronize mapped fields while retaining title translations, additional creators, custom properties, and metadata belonging to other components. Metadata edits reject malformed packets or packets exceeding the 8 MiB / 100,000-markup-token parsing limits; ordinary content edits remain available.
- Digitally signed files can be viewed, but saving modifications invalidates existing digital signatures. The application does not represent drawn marks as cryptographic signatures.
- Password-protected PDFs are decrypted by `src/core/security.js`, which runs pdf-lib's parser with a hook that decrypts strings and streams as they are read (RC4 40/128-bit, AES-128, AES-256 revisions 5 and 6 of the standard security handler). The unlocked working copy is an ordinary PDF; downloads and saves are re-encrypted with AES-256 revision 6 when a password is set. pdf-lib's `ignoreEncryption` flag is never used to edit a still-encrypted file. Certificate security handlers and custom crypt filters are rejected.
- New and replacement text uses Noto Sans for Latin, Greek, and Cyrillic, or Noto Sans KR for Korean (regular and bold). Korean fonts load on demand and exports embed only the used glyphs. Unsupported characters and Korean italic fallback are rejected instead of silently dropping glyphs or styles. Form fields and page marks still use the original Noto Sans coverage; general CJK and complex-script authoring are not supported.

## On-device OCR

Scan & OCR uses **tesseract.js 7.0.0** with **tesseract.js-core 7.0.0** (both Apache-2.0), the WebAssembly build of the Tesseract OCR engine. Recognition runs in a Web Worker on the device; page images never leave it and nothing is fetched from a CDN at runtime. `vite.config.js` serves the assets from `ocr/` beside the app during development and copies them into `dist/ocr/` at build time:

- `ocr/worker.min.js`: the tesseract.js worker bundle.
- `ocr/core/tesseract-core-{relaxedsimd-lstm,simd-lstm,lstm}.wasm.js`: the three LSTM-only cores. The worker picks one based on the browser's WebAssembly SIMD support. The legacy-engine cores are not shipped because the app always runs the LSTM engine.
- `ocr/lang/eng.traineddata.gz`: the English model, Tesseract's `tessdata_best_int` 4.0.0 (Apache-2.0, packaged as `@tesseract.js-data/eng` 1.0.0). It is close to `tessdata_best` in accuracy and much smaller. The model is fetched gzip-compressed and inflated in the worker. It is not cached in IndexedDB, so the browser's HTTP cache is the only copy.

The cores statically link Leptonica, libpng, zlib, libjpeg, LibTIFF and libwebp. Their notices, the worker bundle's embedded notices, and the model's provenance are in `public/THIRD_PARTY_NOTICES.txt`.

`src/core/ocr.js` writes recognized words as an invisible text layer (render mode 3) in its own content stream inside a `/PuterOCR` marked-content sequence. Each word is its own text item, horizontally scaled to its box on the image, so search and selection line up with the scan. Running OCR again replaces the layer, and the layer can be removed without touching the rest of the page. Only English is bundled. Other languages need their own `*.traineddata.gz` under `ocr/lang/`.

## Notice regeneration

`npm run licenses` generates `public/THIRD_PARTY_NOTICES.txt`. `npm run build` runs it before building. Package license changes should be reviewed when dependencies are updated. No application-wide open-source license has been assigned; the requested repository is private.
